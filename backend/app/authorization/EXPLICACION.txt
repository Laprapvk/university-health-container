CARPETA: backend/app/authorization
==================================

¿QUÉ ES ESTA CARPETA?
Todo lo relacionado con AUTORIZACIÓN: "¿qué se te permite hacer?".
Mientras authentication dice QUIÉN eres, authorization dice QUÉ puedes hacer
según tu rol (admin, staff, student).

COMANDOS BÁSICOS DE USO (para el examen):
   - Proteger con rol usando dependencia:
       current_user: User = Depends(require_roles(RoleName.ADMIN))
   - Proteger con decorador (necesitas router = AccessRouter()):
       @router.get("/admin")
       @access(RoleName.ADMIN)
       async def admin_only(): ...

ARCHIVOS:

1. roles.py
   - Define los roles del sistema.
   - RoleName es un enum (String Enum) con valores:
       • ADMIN   = "admin"
       • STAFF   = "staff"
       • STUDENT = "student"
   - DEFAULT_ROLES = conjunto con todos los roles.
   - Estos nombres deben coincidir con el campo "name" de la tabla roles de la BD.
   IDEAS: usar enum evita errores de escritura ("admin" vs "Admin").

2. claims.py
   - Trabaja con las "claims" del JWT (los datos dentro del token).
   - Constantes: SUBJECT_CLAIM ("sub") y ROLE_CLAIM ("role").
   - Funciones:
       • create_claims(subject, role) -> construye el diccionario de claims
       • get_claims(token)            -> decodifica el token y devuelve las claims
       • get_subject(claims)          -> extrae el usuario (sub)
       • get_role(claims)             -> extrae el rol (role)
   - get_claims importa decode_token de forma diferida (dentro de la función)
     para evitar un import circular con authentication.
   IDEAS: una "claim" es una declaración dentro del token (qué usuario y qué rol).

3. guards.py
   - require_roles(*roles):
       • Devuelve una dependencia (guard) lista para usarse con Depends()
       • Resuelve el usuario actual con get_current_user()
       • Si su rol NO está entre los permitidos -> error 403 Forbidden
       • Si no se pasan roles, solo exige estar autenticado
   - Compara current_user.role.name con los roles permitidos.
   IDEAS: 401 = no autenticado, 403 = autenticado pero sin permiso.

4. decorators.py
   - @access(*roles): decorador que marca una función con los roles permitidos.
       • Guarda los roles en el atributo _auth_roles de la función.
   - AccessRouter(APIRouter): router especial.
       • add_api_route() lee el atributo _auth_roles del endpoint.
       • Si existe, agrega automáticamente Depends(require_roles(*roles))
         como dependencia de la ruta.
       • Permite que el endpoint tenga SUS PROPIAS dependencias (Depends) sin chocar.
   IDEAS: el decorador se coloca DESPUÉS (debajo) del @router.get, porque los
   decoradores se aplican de abajo hacia arriba.
   Ejemplo correcto:
       @router.get("/x")
       @access(RoleName.ADMIN)
       async def x(): ...

5. __init__.py
   - Exporta solo roles y claims (módulos SIN dependencia de FastAPI).
   - No exporta guards ni decorators en __init__ a propósito,
     para evitar imports circulares con authentication.
   - Uso: from app.authorization import RoleName, get_role
         from app.authorization.guards import require_roles
         from app.authorization.decorators import access, AccessRouter

RESUMEN: LA CADENA DE AUTORIZACIÓN
   @access(RoleName.ADMIN) -> AccessRouter lee _auth_roles
   -> inyecta Depends(require_roles(RoleName.ADMIN))
   -> require_roles llama a get_current_user (autentica)
   -> compara user.role.name con "admin"
   -> si no coincide: 403 Forbidden.
