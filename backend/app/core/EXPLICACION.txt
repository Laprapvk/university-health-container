CARPETA: backend/app/core
=========================

¿QUÉ ES ESTA CARPETA?
Contiene la configuración general del back-end y utilidades transversales
(cosas que se usan en varias partes del proyecto).

ARCHIVOS:

1. config.py
   - Define la clase Settings, heredada de BaseSettings (pydantic-settings).
   - Lee la configuración desde variables de entorno o de un archivo .env.
   - Valores que maneja:
       • PROJECT_NAME                -> nombre mostrado en la documentación
       • API_V1_STR                  -> prefijo de la API: "/api/v1"
       • DATABASE_URL                -> conexión a PostgreSQL (async)
       • REDIS_URL                   -> conexión a Redis (caché/colas)
       • SECRET_KEY                  -> clave secreta para firmar los JWT
       • ALGORITHM                   -> algoritmo de firma: "HS256"
       • ACCESS_TOKEN_EXPIRE_MINUTES -> duración del token (30 min)
   - Al final crea settings = Settings(), la instancia única que se importa
     en todo el proyecto: from app.core.config import settings
   IDEAS: la configuración no está "quemada" en el código; se puede cambiar
   con un archivo .env sin tocar el código.

2. security.py
   - ARCHIVO PLANIFICADO (está vacío).
   - En un proyecto estándar aquí se ponen utilidades generales de seguridad.
   - En ESTE proyecto, la seguridad de autenticación vive dentro de
     app/authentication/security.py (hash de contraseñas + JWT).
   - Se dejó como "placeholder" para utilidades futuras.

3. __init__.py
   - Marca la carpeta como paquete de Python. Está vacío.

RELACIÓN CON EL RESTO:
   - config.py se usa en: main.py, db/session.py, authentication/security.py.
   - SECRET_KEY es lo que hace válidos los tokens: cualquiera que la conozca
     podría firmar JWT falsos. Por eso en producción debe ser secreta.
